## Cross-plan safety defects (specific)

**S1 — The adds-ban as written can block EXITS of losing shorts.** P1-3 says reject "`add`/`buy`-side increase when uPnL<0"; P4-5 says reject "`buy/short` adds when uPnL<0". On a losing short, a **buy is a cover** — run_engine maps sell→short/buy→cover on futures (memory: futures-runs-short-mapping). A side-keyed implementation blocks the desk from covering exactly the losing shorts the rule exists for (run-1099 class). The gate MUST key on *position-increasing* intent (|qty after| > |qty before|), never order side, with a wiring test on a losing short cover. P3-5's phrasing ("NO add while uPNL<0 — explicitly covering shorts") is closest to right but still needs the intent test.

**S2 — Exit-suppression (P4-2 MIN_HOLD_HOURS=24; P5-6 arm B =12h) removes the dominant exit author and interacts with the mark-blackout failure mode.** The desk authors 72.9% of exit fills (R2). The SL/TP watcher has **no mark-age check** (FACTS code map) and is **silent-open on frozen marks** (08-29 incident: 62-min blackout). Convert desk sell/cover→hold and, during a blackout, *nothing* can exit for the hold window. Required: (a) whitelist every platform exit author — max_loss, ratchet/trail, `at_time`, adapt/desk-retire flatten, `fleet_stop_all`, armed_exit — P4 says only "not a stop"; (b) min-hold must fail-open when mark age exceeds a threshold. Without both, this is new unbounded-risk code on the money path.

**S3 — `REGIME_FILTER_ENABLED` is one GLOBAL env** (`strategy_config.py:103`; gates at `automation.py:528,729` cover all agents/markets, including any live-account rule). P5-7's "enable only inside this arm" is **impossible as an env-flip** — it needs scoping code. P4-7 flips it platform-wide on bands `regime.py` itself labels "UNVALIDATED PLACEHOLDERS" — that enforces size-halving/no-buys on live paths from placeholder thresholds. P2-4's shadow/log-only mode is the right design but **does not exist in code** (verified: only the boolean gate exists) — it is new code, not "env-flip + small code" as costed. Only P2's sequencing (shadow → measure → enforce) is acceptable; P4-7 as written is not.

**S4 — Ratchet fee fix is global, not per-market.** `BREAKEVEN_FEE_RATE` env already exists (run_engine.py:915 — so a kill switch exists without code), but it is one constant across all markets while prod runs FEE_PER_MARKET=true. Setting 0.00045 globally under-arms us-stock/forex/futures ratchets — locking "protected" levels that are below true breakeven there. Fix must call `fees.fee_rate(market)`.

**S5 — Order-of-ship hazard in the leak fix.** The RR_FLOOR term at run_engine.py:7577 exists (per the in-code comment) "so it can never convert an entry into an rr_floor skip" — a later R:R rail re-checks the bracket. Deleting the term *without* the simultaneous stop clamp leaves 0.30% targets against 1.5–8% stops, which the downstream rail then skips → entry drought → pressure to loosen a gate (owner-prohibited). Leak deletion and stop clamp must be **one atomic ship** (P1-1/P5-3 imply this; make it explicit). Also scope the clamp: P1 names `STOP_CAP_PCT_CRYPTO`, P5 names global `STOP_CAP_PCT` — a global 0.5% stop on GC/forex is a different (untested) trade; crypto-scope it.

**S6 — Agent 5 is user 4 (yoojinbe), not the owner's test account** (agents.tsv; owner test = user 5/agent 6). Pausing a possibly-real user's automation is a consent/product act, and the standing owner rule is "build the path, don't patch the row." Verify ownership first; implement the pause as a platform mechanism with an env/admin kill, not a DB row edit. Fleet-38 exposure: none (fleet 32).

**S7 — Agent-6 backfill UPDATE is a live behavior change, not just display.** `signals.pnl` feeds desk_reference (the desk reads its own fill ledger) and adapt feedback. Backfilling 174 rows changes live desk inputs mid-flight. Acceptable, but: DB backup first, off-hours, and note it in the ship as a desk-input change with before/after decision sampling.

**S8 — P2-5 forced FULL routing re-risks the known LLM oversubscription** (~5× at ~178 calls/h; the no-verdict regression). "AI router may not downgrade" needs a call-budget cap and a no_verdict-rate falsifier, else the fix that restores entries silently kills verdicts platform-wide.

**S9 — Env-name drift:** the same adds-ban is `MAX_ADDS_INTO_LOSER` (P1), `MAX_ADDS_UNDERWATER` (P4), `ADD_INTO_LOSER_BLOCK` (P5). Rollout must canonicalize one name or three sessions will ship three half-gates.

**Gate-loosening check:** no plan loosens a platform entry gate. P1-4/P2-1's prompt line ("do not hold or retire because R:R looks inexpressible") is the borderline case — an imperative *against holding* edges toward manufacturing entries via prompt.
