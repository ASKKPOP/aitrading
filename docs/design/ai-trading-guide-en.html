STEP 5Signal Fusion — Three Families, One Score

The three signal families — quant, sentiment, psychology — are fused into one score per symbol. When AI fusion is on (the default in production), the model weighs the full factor snapshot itself and returns its own component weights; the fixed weighted sum below is the deterministic fallback, used when the model is unavailable. Each result is labelled with its source (AI / rule / rule-fallback). Read-only (GET); this step never places an order.

fallback = 0.5 × quant + 0.3 × sentiment + 0.2 × psych   (components clamped −1 ~ +1; missing ones excluded and re-normalized). On BOTH paths: psychology never trades alone, and its weight can never exceed 0.3 — an AI verdict declaring otherwise is discarded.

Framework trigger mapping (implemented exactly as plan §4)

DirectionTriggerThreshold (default)

The psychology cap is structural. Two guarantees hold on both the AI and the fixed-weight paths. First, psychology never trades alone: with no quant and no sentiment the verdict is forced to hold by construction — the model is not even consulted, so it cannot argue past the rule. Second, the psychology weight can never exceed 0.3 (PSYCH_WEIGHT_MAX): the fixed-weight path re-normalizes any excess away; the AI path discards a verdict that declares a psych weight above the cap and falls back to the deterministic score. "No psychology-driven trading" is a constraint, not a guideline.

STEP 6AI 4-Analysts + Trader Debate — The Final Call

This is the engine that makes the actual trade decisions. Four analysts each write a brief, then the trader + risk team debate to produce one decision and a written report.

  • With an LLM — the configured provider (OpenAI, Gemini, Grok, Qwen, GLM, local, OpenRouter, Anthropic) generates the briefs and debate.
  • Without an LLM — a per-role deterministic rule-based fallback produces briefs and decisions in the same format from the same data. The engine never stalls.
  • Real bug found and fixed in red-team review: rule-based confidence used score instead of |score|, making sell decisions unreachable → fixed (105d7e6).

STEP 7Automation Rules — What the User Decides

The scope and intensity of automation are entirely user-configured. An automation tick runs every 60 seconds and executes only rules that are "enabled and due". The UI offers three modes — ① Simple (pick coin & risk appetite only), ② Standard (tune recommended presets), ③ Expert (full parameter control).

STEP 8Risk Gate — The Framework's "Mandatory" Item

Every automated order must pass the triple gate, no exceptions. The gate can only shrink or reject an order — never enlarge it.

What the Kelly formula does

f* = W − (1 − W) / R   ·   W = win rate, R = avg win/avg loss   ·   order cap = ½ f* × equity (cash + holdings value)
  • W and R are computed from the agent's own close-out journal (average-cost replay, capped at the latest 5,000 records) — its own track record, not anyone else's.
  • Under 10 closed trades there is no statistical basis, so no adjustment is made (guards against overconfidence).
  • f* ≤ 0 means "no edge" — that buy is rejected. A reduced order under $1 is meaningless, so it is rejected too.

STEP 9Fills and Position Management — All Paper, All on the Ledger

Fills use exactly the same ledger as manual trades: a signals row (signal_type='automation') + position update + cash update + fees — inside one transaction.

  • Buy: check cash → fill → register SL/TP on the position row in the same transaction (gate-computed values, default −5% / +10%).
  • Sell: executes only against an existing long position — otherwise skipped with "no long position to sell". No shorting.
  • US stocks: no fills while the market is closed — analysis and logging only (skip_reason saved).
  • Price tracking: unrealized P&L is computed from price_fetcher polling, no broker — the watcher judges SL/TP against these prices.
  • Real accounts: account_type='live' (formerly real) rules route real orders through your connected trading gateway — nine venues (Alpaca, Binance, IBKR + the 2026-08 regional expansion: Bybit, OKX, Kraken, Crypto.com, Upbit, KuCoin), protected by per-broker terms consent, the live allowlist (new venues run shadow first) and an initial $1,000 per-order limit ($1,500 for Webull). See the Live Trading Gateway doc for details.

§11Three Perspectives — Trader · CEO · QA

TTrader's view — "How do I trust and use this system?"
  • Discipline is enforced in code. The psychology weight cap (0.3), Kelly minimum sample (10 trades), confidence gate (0.65) — even when the human gets excited, the system cannot.
  • Every signal carries evidence sentences. Not just "BUY 0.36" but "price above MA20 + funding neutral + F&G extreme fear, recovery not fired" — read it and decide whether you agree.
  • Losses are cut at two layers. Per position (SL −5%) and per account (daily $1,000). Watcher closes bypass the gate, so exit is always possible even in a lockout state.
  • Recommended progression: ① watch signals only for a few weeks with auto_execute off → ② once your own journal reaches 10 trades and Kelly turns on, automate with small size → ③ tune min_confidence to your own temperament. Don't rush to lower it to 0.5 — the conservative 0.65 default is there for a reason.
CCEO's view — "Why this design is a product edge"
  • Positioning: not a "guaranteed-profit bot" but an Intelligent Automate Agent — a platform of measurable signal collection + disciplined automation. Evidence sentences, snapshots, and reviewability are the differentiators, and they lower regulatory and trust risk at the same time.
  • Paper-first is a strategy. Every rule starts on the simulator — you verify the system's skill risk-free, and when ready you connect a gateway and step up shadow (sandbox comparison) → live (real orders). The live trading gateway is already running.
  • Cost structure: the entire current pipeline runs on free sources — scales at zero marginal cost. LLMs and paid data (whale/liquidation) are optional layers added after revenue.
  • Roadmap order: P6 whale/liquidation (paid sources) → deeper backtesting → real broker integration → agent marketplace. Each stage builds on the previous stage's data.
  • Risk management is the brand: "a platform where psychology-driven trading is structurally impossible" is a marketing line and a fact at the same time — provable in code.
QQA's view — "What is verified, and how"
  • 1,100+ tests passing (including 126 new phase tests: risk_engine·routes_risk·psych_feed·quant_crypto·scanner·signal_fusion·routes_signals·signal_feed_snapshot).
  • Safety invariants pinned by tests: only simulator fills · sells require a held position · closed-market skip · no orders on real accounts · the gate can only shrink/reject.
  • Fail-soft applied throughout: when an external source fails, only that component drops (named in the missing array) and the rest of the snapshot saves. Bad env weights fall back to defaults instead of a 500.
  • Stage isolation: all 5 phases default to env-flag off — in a production incident, one flag shuts off just that stage.
  • Red-team track record: 6 expert perspectives + red-team review caught and fixed the "sell unreachable" bug before deploy — proof the review process actually works.
  • Live verification (2026-07-15): fusion, psychology, scanner, and risk endpoints all confirmed serving real data on sooppiy.com (F&G 25, BTC RSI 55.05, scanner candidate BSBUSDT ×3.52), no regressions.
  • Remaining verification: long-run observation of watcher closes (collect real SL firings on staging), scanner mention-baseline accumulation (≥3 scans), monitoring for a real automatic breaker trip (3σ).
