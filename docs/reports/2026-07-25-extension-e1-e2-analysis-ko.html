E1 — 상황별 라우팅: 극단 상황엔 AI, 중간 상황엔 알고리즘 RECOMMENDED

아이디어: 분석 결과가 고이벤트 / 고위험 / 고수익으로 나타나면, AI가 권장하고 실행하도록 합니다 (알고리즘은 극단 상황의 모든 파라미터를 다 담아낼 수 없습니다). 일반 상황(보유 / 통상)에서는 프로그래밍된 결정론적 알고리즘으로 실행합니다 — 저렴하고, 감사 가능하며, 예측 가능합니다. 이는 타당한 아키텍처이며, 매 주기마다 전체 분석을 실행하는 비용 문제를 직접 해결합니다.

이것이 맞는 이유
  • 비용: 전체 사이클 중 약 15~20%에서만 풀 AI를 사용 → 현재 실행 중인 전면 풀 모드보다 약 80% 저렴하면서도, 인간 요인 판단이 중요한 곳에는 정확히 AI를 유지합니다.
  • 감사 가능성: 일반 운영은 결정론적입니다 — 재현 가능하고, 백테스트 가능하며, 설명 가능합니다.
  • 테일 품질: 테일은 Fleet 16이 손실을 본 지점입니다 (전량 숏 북에 대한 랠리) — 바로 풀 데스크가 사고해야 할 지점입니다.
위험 & 가드레일
  • AI는 리스크 엔진을 절대 우회하지 않습니다 — 두 경로 모두 동일한 게이트에서 끝납니다 (Kelly, 익스포저, 스탑, 트레일링). 타협 불가능한 불변 조건입니다.
  • 페일-클로즈드: 핫 사이클에서 AI 호출이 실패하면 → 보류 + 스탑 유지, 이벤트 도중 알고리즘으로 조용히 넘어가지 않습니다.
  • 임계값 보정 백테스트 하네스가 필요합니다 (plan #1) — 위의 보수적인 트리거로 v1을 배포하고, 데이터로 튜닝합니다.
  • 경로 기록 (route: ai|algo + trigger) 모든 결정 이벤트에서, 사이클별로 동작을 설명할 수 있도록 합니다.

E2 — 핫이슈 데몬: 모든 사용자의 RUN 심볼에 대한 시간별 AI 감시 RECOMMENDED

당신의 아이디어: Sooppiy는 매시간 모든 사용자의 실행에서 전체 심볼을 스캔하여 (예: 사용자 3명 · 심볼 11개), 핫 이슈(ROI 변동, 모든 기관의 경제/정책 변화, 기술적 브레이크아웃, 뉴스 및 소셜 급증)를 감지하고, 영향을 받은 각 사용자에게 알리며, 각 사용자의 Trading Master에게 의사결정 지점을 전달하는 데몬입니다. 워커는 이미 모든 입력 피드를 스냅샷하고 있으므로 — 이는 대부분 조립과 팬아웃 레이어입니다.

이미 존재함 (프로덕션에서 검증됨)
  • 피드: policy_feed · psych_feed (F&G, 쇼크) · social_feed · 시장 뉴스 / 매크로 / ETF 흐름 스냅샷 — 모두 워커 스케줄에서.
  • 알림: send_alert 사용자별 언어 포함 (5개 언어 카탈로그가 프로덕션에서 운영 중), 중복 제거 키.
  • Master 레이어: ai_automation_state + 신호를 수신/처리하는 fleet supervisor.
구축할 항목
  • hot_issue_daemon.py 워커 태스크 + hot_issues 테이블 (symbol, trigger, severity, ai_read, ts).
  • 트리거 임계값 (각 피드 자체 히스토리 대비 z-점수) + 심볼별 쿨다운 (동일 심각도에서 N시간 미만 재알림 없음).
  • E2-B′ 사용자별 검증 레이어 — 핫 이슈 × 각 사용자의 북(포지션 방향, 레버리지, 스탑까지의 거리, 논제)을 조인함; 결정론적 관련성/중대성 필터, 그다음 중대한 사용자당 하나의 개인화된 AI 검증. 임계값 이하에서는 무음.
  • 알림 카탈로그를 위한 새로운 i18n 메시지 id (메모 노트에 따라 네이티브 검토 필요) — 포지션별 문구로 매개변수화됨.
  • Master "신호에 따라 행동" — v1: 알림 + 결정 지점 노출 + 다음 사이클을 AI로 라우팅. 신호에 따른 자동 거래는 옵트인 phase 2에서만.
주요 리스크 — 알림 피로: 과도하게 알리는 시간별 AI 워처는 일주일 이내에 음소거됩니다. 심각도 하한선, 심볼별 쿨다운, 그리고 "상태 변경" 규칙은 탐지 자체만큼 중요합니다.

LLM 비용 — 라우팅이 전면 풀 모드보다 나은 이유

45분 주기로 동작하는 4-run 플릿의 일일 결정 계층 LLM 호출 수(32 cycles/run/day), 그리고 11개 심볼에 대한 데몬 호출 수. E1은 항상-풀 모드 대비 약 ⅕ 비용으로, 풀 데스크가 실제로 이익이 되는 곳에서만 이를 유지합니다. E2의 사전 필터는 시간당 AI 감시를 경제적으로 가능하게 만듭니다.
