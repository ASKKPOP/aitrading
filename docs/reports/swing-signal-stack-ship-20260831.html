01 · The blueprint, as built

Six feeds, five scores, one gate

Every score runs −100…+100. The composite is the weighted sum, renormalized over feeds that actually have coverage — a missing feed gives up its weight instead of silently dragging the total toward zero. Nothing trades unless the quantitative axis (technicals) and the qualitative axis (sentiment + thesis) agree; everything else is a WAIT with a written reason.

The engine is pure — no I/O, no environment flags — so the same code is unit-tested (25 tests; a 4-mutant injection pass all caught), driven by the simulator, and importable by the live platform later. The doc's own worked example lands at exactly 46.1, pinned by test.

02 · The experiment

Hypotheses first, then the data

Per the house rule, the falsifiers were written before any candle was fetched. Universe: ten US stocks, five crypto majors. All history real — Yahoo and OKX daily bars, VIX/10Y/DXY, CNN and alternative.me Fear & Greed. A control arm trades the same exits on technicals alone (≥ +40, no agreement rule, no blackout), so the stack's judgment layer is what gets measured, not the playbook.

  • H1 — stack BUY entries have positive net expectancy. Falsifier: ≤ 0R, or n < 5 → inconclusive.
  • H2 — the two-axis WAIT rule beats quant-only per trade. Falsifier: control expectancy ≥ stack expectancy.
  • H3 — the 24h event blackout actually fires in a month containing NFP, CPI, Jackson Hole and PCE. Falsifier: zero vetoes.
03 · What the data killed

v1 never traded — and that was the finding

Killed hypothesis · recorded 2026-08-30

The first sentiment mapping scored only the extremes of Fear & Greed (contrarian at ≤25 and ≥75, zero everywhere between). CNN F&G spent the entire month between 40.7 and 66.6 — so sentiment read 0.0 on 100% of days, the qualitative axis stayed flat, the two-axis rule could never agree, and the stack sat in cash for a month while the control took 30 trades.

06 · The crawl, operationally

What service runs the six crawls — how, when, from where

The service is routes_admin_swing_feeds.py, running inside the sooppiy-backend FastAPI container on production. It is a pull-on-demand crawler, not a daemon: there is no cron loop and no background schedule yet. A crawl happens in exactly three situations, and nowhere else:

  • An admin opens the Feed status tab → GET /api/admin/swing-feeds/status fires all six probes concurrently (one thread each, 6-second timeout per source). The result is cached in-process for 60 seconds, so console refreshes within a minute serve the cache and never touch the upstreams.
  • An admin clicks “Re-probe now” → ?refresh=true bypasses the cache and probes live. This is the path that drew the real faireconomy 429 during verification — the cache is the rate-limit protection.
  • The research simulation runs → research/swing_stack_sim_20260830.py pulls the deep history (up to 1 year of daily bars, full F&G history) once per invocation, from the workstation, not the server.
