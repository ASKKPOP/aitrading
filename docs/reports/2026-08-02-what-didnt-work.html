1 · What didn't work

실패한 것들 — 심각도 순

Close intents inverted into short-adds Fixed today

청산 의도가 숏 추가진입으로 역전 — 금일 수정 배포됨

The desk said intent: close ("lock in profit"), but the legacy futures verb mapping (sell→short) added to the short instead of covering. 7-day shadow data: 54 close intents — 7 inverted into adds, 10 stranded on hold.

Run 919 (SOL): said "close" 4 consecutive cycles while the engine tripled its short (2.7→84.6 SOL), paid $5.57 in fees, and the trailing lock finally flattened it: peak +$6.79 → realized −$0.83. Run 921 repeated the identical inversion at 12:05Z.
Fix: RUN_ORDER_INTENT=apply (Plan 17 phase-1, exits-only) enabled 12:20Z, backup .env.bak-20260802-intent. Verified live 5× — every close/reduce since executed exactly as intended (920 banked +$0.29 within 13 minutes of the flip; 916 scaled out 3× for +$3.08).

Intra-horizon churn — desks abandon their own plan in ~30 minutes Open · top lever

지평 내 단기회전 — 데스크가 스스로 정한 보유 계획을 30분 만에 파기 (미해결 · 최우선)

8 round-trips today, net ≈ −$4.9. Every one had a desk-stated horizon days in the future (e.g. "hold until Aug-4"), then exited within 1–2 cycles. Fees dominate: several legs were price-positive but fee-negative. Worst rationale: 925 closed "to eliminate exposure while the downtrend persists" at confidence 0.72 — self-contradictory.

The order_plan.horizon machinery that would prevent this already exists but is shadow-only (horizon_shadow.would_hold journaled every time). Recommendation: promote horizon enforcement — hold intent-exits inside the stated horizon unless a stop/risk trigger fires. This is a code change; evidence file is ready for review.

Stale run-peak killed a fresh position in 28 seconds Open

잔존 런 피크가 신규 포지션을 28초 만에 사살 (미해결)

Run-level peak_pnl_usd survives after the book goes flat. Run 921 opened a small probe at 15:37:33 with a tight desk trail (arm $0.8); the trail armed against the stale +$2.74 peak from a position closed hours earlier and fired 28 seconds later at the same price, stopping the whole run. Cheap this time (−$0.09 fees) — but the same mechanism can decapitate a healthy winner.

Fix candidate: re-anchor peak tracking whenever positions → 0 (or track trail against per-position peak).

Desk-authored trails that can never arm 3 instances

발동 불가능한 데스크 트레일 설정 (3건 관찰)

Desks set trail_arm_pct: 40 → activation ≈ $80–240 on positions whose maximum possible profit is ~$14. The trail is decoration; the position runs unprotected (the exact shape that hurt 919). One desk self-corrected to 5% later — the capability is there, the rail is not.

Fix candidate: rail trail_arm_pct ≤ target_pct (clamp-down, same monotone philosophy as the other rails).

LLM markdown-bold corrupted JSON → decisions lost 2 instances

모델이 JSON에 마크다운 볼드를 섞어 결정 손실 (2건)

gpt-oss returned **"confidence": 0.66,** inside the decision JSON. Parse fails → the cycle degrades to a wasted conf 0.0 hold (runs 923, 928). Each instance is a paid LLM call producing nothing.

Fix candidate: strip ** (and stray markdown) before JSON parse in the decision parser — one line, test with the captured payloads.

Phantom 15%/8% house bracket blocks entries 2 instances

출처 불명 15%/8% 기본 브래킷이 진입 차단 (2건)

When the desk returns no explicit stop/target, a reward-15% / risk-8% bracket appears (source: not run config — likely user-level risk defaults) and the R:R floor refuses it every time (1.875 < 2.0). Both blocks today were arguably merciful (choppy tape), but a default bracket that always fails the floor means bracket-less entries are silently impossible.

Action: find the 15/8 source; either fix the default to pass (e.g. 8%/16%+) or decide bracket-less entries should be refused — explicitly, not by accident.
