## What review should look for, in priority order

1. **Trading-term register.** The glossaries the pipeline enforced:
   long = 롱 / ロング / ลอง / mua (long) / beli (long); short = 숏 / ショート /
   ชอร์ต / bán (short) / jual (short); cover = 커버 / 買い戻し / ปิดชอร์ต /
   mua bù / tutup short. A native trader should confirm these read as market
   vocabulary, not dictionary translations.
2. **The deliberate bilingual glosses.** vi/id keep `(long)`/`(short)` in
   parentheses on purpose; `gateway-ko` keeps its 15 English section kickers
   on purpose (the ko original was written that way). Do not "fix" these
   without deciding the convention product-wide.
3. **Formality level.** ko uses 합니다체, ja uses です/ます, th uses คุณ, vi uses
   bạn, id uses Anda — consistently, but a native ear should confirm the
   register suits a trading product.
4. **Number/date idiom.** Amounts are passed through verbatim by design
   (`-$1,099`, `29.00`); check no locale expects different separators badly
   enough to matter.

## Known accepted quirks (reviewed, left as-is)

- `Run #N` stays Latin in ja templates (ko uses 런, th uses รัน) — flagged
  2026-07-29, judged consistency-not-defect; a reviewer may standardize.
- Journal/book titles, author names, product name Sooppiy, tickers and env
  vars stay English everywhere, deliberately.
- English-template notification rows in the history are consistent English
  (rendered while the account language was `en`) — not defects.

## How to re-run the pipeline after edits

```bash
.venv/bin/python docs/design/_gen_doc_translations.py --only <group> --langs <lang>
.venv/bin/python service/server/build_guide_content.py
```

Structural safety is automatic (text-node splicing, echo repair, ampersand
re-escaping, byte-identical round-trip when nothing translates). Editing a
generated file BY HAND is fine — the pipeline only writes files listed as
missing, so a hand-corrected translation is not overwritten unless you
delete it.
