Findings — all fixed

1 — SPA catch-all swallowed every unmatched /api/* path FIXED
Root cause of findings 1–3 in the pre-fix run. routes_misc.py registered @app.get('/{path:path}') as an SPA fallback that matched everything, so any unknown API path returned HTTP 200 + index.html. nginx was innocent — it proxies /api/ straight through. A dead backend was indistinguishable from a healthy one for any status-code monitor, and /api/leaderboard, /api/agents, /api/portfolio all silently returned the SPA.

Fix: unmatched /api/* now returns JSON 404 {"detail":"Not Found"}. Non-API paths still fall through to index.html, so client-side routing is unaffected — verified against /, /trade, /settings, /some/deep/path and /apitest, all still serving HTML 200.
2 — No liveness signal existed FIXED
There was no /api/health route anywhere, yet curling it returned 200 via the fallback. Fix: added GET /api/health returning {"status":"ok","database":"ok"}, or 503 with "degraded" when the database probe fails. It deliberately reports no database identifiers — the existing get_database_status() exposes DB user, hostname and port, and this endpoint is public.
3 — Documented prefix /api/claw/* never existed FIXED
The handoff doc's architecture section claimed agents call /api/claw/*. No such prefix was ever registered; real routes are /api/agents/me/*. Because unmatched paths returned 200 + HTML, a status-code test of /api/claw/agent appeared to pass — it produced a false positive in this engagement's own earlier verification before body assertions were added. Doc corrected; with finding 1 fixed, the same mistake now fails loudly with a 404.
4 — Concurrent deploys shared an unlocked ~/sooppiy/.env FIXED
The file changed from 9206 to 9566 bytes mid-session while a parallel session deployed, and production moved across four image tags in roughly thirty minutes. The runbook mutated it with sed -i with no lock, so overlapping deploys could clobber an image pin or strand backend and worker on different tags. Fix: the runbook now holds flock /tmp/sooppiy-deploy.lock across both the sed and the compose up, not just the sed.
5 — Everything the account touches still works PASS
All 15 agent-token endpoints, 4 user-token endpoints, both market-data endpoints and all 3 auth-enforcement checks returned correct JSON, unchanged before and after the fix. Login yields user_id 5 with subscription_status: active; wrong password issues no token; unauthenticated and garbage-token requests are refused with JSON 401.

How the fix was made

Tests were written first and confirmed failing (AssertionError: 200 != 404) before any production code changed. After the fix the full backend suite ran 1421 passed, confirming nothing depended on the old catch-all behaviour. CI-gated ruff (F401,F811,F821,F841) is clean.

Deployed to production via the runbook under validation — dated tag 20260720-apifallback, flock-guarded .env edit, backend and worker recreated together, SPA republished with the trailing-/. extraction. Backend and worker both on the new tag with 0 restarts and 0 tracebacks; the worker resumed its snapshot cycles.

Deploy runbook — executed, not assumed

The runbook in docs/plan/03-session-handoff.md was run end to end against production: built a dated tag, repointed SOOPPIY_IMAGE, recreated backend and worker via compose, republished the SPA, then rolled back. Both directions finished with 0 restarts, 0 tracebacks, and matching bundle hashes.

The exercise was made safe by first proving the backend Python source in the live image was byte-identical to origin/main (SHA-1 of the sorted per-file digest list matched at 6da68d754812546b), making the rebuild a code-level no-op.

Method

39 checks driven by curl against the live public endpoints, authenticating as info@askkpop.com through the documented login → agent-token flow. Read-only apart from login and the idempotent agent-token mint. Each check classifies the response body as JSON, HTML, EMPTY, or OTHER and asserts on that classification rather than the status code.

The suite was run twice before the fix and twice after; within each stage the verdict column was byte-identical across passes. An earlier draft of the suite reported four false failures caused by two defects in the harness itself — a collision with bash's readonly UID, and use of the non-existent /api/claw/* prefix. Both were fixed before any results were recorded.
