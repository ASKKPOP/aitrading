Admin subscription alerts & per-user trading mode

Two admin features, both assembled from patterns already in the codebase — the platform_settings console store, the alerts email/SMS senders, and the admin Users query. No new infrastructure.

1 Alert you when someone requests a subscription

Whenever a user submits a request on sooppiy.com/subscribe, you get an email and/or SMS carrying who, which plan, and the reference to act on — so you can approve straight from the message.

Where you configure it

A new GET/PUT /api/admin/settings/alerts — an exact mirror of the existing /settings/payment route. Values live in platform_settings, editable from a new “Admin alerts” card in the console Settings tab. No deploy needed to change your number.

  • admin_alert_email — env fallback ADMIN_ALERT_EMAIL
  • admin_alert_phone — env fallback ADMIN_ALERT_PHONE

Empty field = that channel is off. Same fail-soft rule as the USDT address.

2 Show each user’s trading mode — simulator vs real

The admin Users list gains one Trading column that answers “who is trading real money?” at a glance. It rolls up each user’s automation rules to a single mode.

Rollup precedence

A user’s badge = the highest-risk account_type across their agent’s rules. Legacy real folds into live.

🔴 Live

🟡 Shadow

Any live rule → 🔴. Else any shadow → 🟡. Else has rules → ⚪. No rules → —.

One query, no N+1

A correlated subquery added to the existing GET /api/admin/users. Works on SQLite and MySQL.

CASE
  WHEN SUM(c.account_type IN ('live','real')) > 0 THEN 'live'
  WHEN SUM(c.account_type = 'shadow')     > 0 THEN 'shadow'
  WHEN COUNT(*) > 0                        THEN 'simulator'
  ELSE NULL END  -- as trading_mode

3 Scope & verification

Deliberately NOT building (tell me if you want any)

  • No new in-app admin notification feed/bell — email + SMS only, as asked.
  • No per-rule drill-down from the badge — the Automation tab already lists rules.
  • No admin-SMS tier gating — it’s your own number, low volume.

How it’s verified

  • Unit: both channels fire; empty-config skips; a sender exception never propagates.
  • Unit: rollup precedence — live > shadow > simulator; real→live; no-rules→null.
  • Mutation-checked: inject a bug, confirm the test fails (per your rule).
  • Manual: submit USDT on local /subscribe → one alert; set a live rule → badge turns 🔴.
