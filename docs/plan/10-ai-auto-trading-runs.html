2 · System architecture

Two processes (API + worker) that cannot share memory; the DB is the source of truth, Redis pub/sub is the low-latency plane, and the browser renders from one multiplexed WebSocket.

The worker cannot reach the API's WebSocket connections directly — everything crosses via the DB (always) and Redis (when enabled). With Redis off (dev default), the hub tails run_events at 1.5s and polls positions.current_price for ticks: same protocol, higher latency.

3 · Run lifecycle (state machine)

A run is a database row, never an in-memory task — it survives deploys and crashes by construction. Stops evaluate on every 60s scan (running and paused), decoupled from the LLM cadence, and fail closed: stale marks and evaluation errors pause entries and alert.

Flatten follows the codebase's watcher convention — exits bypass entry gates ("they only reduce risk"); only a manual breaker HALT blocks it. If blocked past a bounded retry window, the run lands in the explicit terminal stopped(positions_held) with an alert — it can never wedge in stopping.

4 · One trade cycle — exactly-once by construction

The verification round found the exactly-once hole (a slow-but-alive worker whose lease expires mid-LLM-call could double-trade under a fresh seq). Closed with three mechanisms working together:

Capacity math: at ~60s per LLM call, 4 slots ≈ 4 runs at 1-min intervals / ~20 runs at 5-min. RUN_CYCLE_CONCURRENCY is env-sized from Henry's target run count (open question 8), on a dedicated thread pool with a per-provider rate limiter.

5 · Telemetry & WebGL2 dashboard

Durable plane — run_events

  • Monotonic seq per run, UNIQUE(run_id, seq); recovery via last_event_seq
  • Trade & state events written inside the trade/transition transaction — a committed trade can never be missing from the journal
  • Telemetry (equity, gate-skips) is fail-soft; equity written on change + 60s heartbeat (not blind 10s spam)
  • Pruning is equity-only (24h full / 15-min→7d / hourly→30d / daily→365d); decisions & trades never pruned
  • Replay: backfill > from_seq (cap 500 → snapshot-reset); contiguity guaranteed within the unpruned window

Live plane — hub & WebSocket

  • One multiplexed WS /ws/runs; short-lived single-use ticket auth (no session token in query strings)
  • Per-sub authorization on every sub frame — the run's agent must belong to the connection principal (closes the cross-tenant P&L leak)
  • Hub tracks last-relayed seq per run → backfills gaps from DB before forwarding; resync_required on pubsub reconnect (pub/sub is at-most-once and cache.publish fails silently)
  • Ticks coalesce ≤10 Hz; honest floors — crypto sub-second only with ENABLE_PRICE_PUSH; us-stock 60s (Alpha Vantage 1-min bars, budgeted in Phase 0)
  • No Redis (dev default): DB-tail for events + positions-poll for ticks — same protocol

WebGL2 kernel — zero new dependencies

Extracted from AnalysisPipelineViz: shader plumbing, DPR sizing, on-demand rAF, WebGL2-null fallback. Built new (honestly budgeted): context-loss restore, ring buffers, instanced line strips, scissor grid.

  • All grid tiles render from ONE canvas/context (gl.viewport + gl.scissor) — browsers cap WebGL contexts at ~8–16
  • Float32Array ring buffers + bufferSubData; min/max-per-column decimation → 100k+ points at 60 fps
  • Every tile shows a last-update age badge — polled markets must not pretend to be live
  • Canvas2D fallback shares the ring-buffer layer; hidden-tab rAF throttling absorbed + fast-forward on visibilitychange
  • Route /runs/live (avoids the sidebar prefix-match double-highlight on /monitor/*); run management = a "Runs" tab inside /automation

6 · Data model

Every change lands twice — database.py SQLite DDL + alembic 0022 MySQL DDL. All new timestamps pinned to %Y-%m-%dT%H:%M:%SZ (mixed ISO formats mis-order lexicographically — fatal for lease expiry).
