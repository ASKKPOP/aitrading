1. ภาพรวม — ทักษะอยู่ที่ไหนและทำงานที่ไหน

กล่องเส้นประคือสมมติฐานเดิมที่การออกแบบนี้ต้องทำลาย: repo skills/ เป็นพื้นที่เผยแพร่สำหรับ external agent และถูกยกเว้นจาก Docker image — ดังนั้นเนื้อหาทักษะจึงอยู่ใน DB และแคตตาล็อกพื้นฐานมาพร้อมกับโค้ดและ seed ตัวเอง

2. ขั้นตอนวงจรการตัดสินใจ — ทักษะเข้าสู่วงจรการเทรดสดที่ไหน

💡 ทำเครื่องหมายจุดแทรกทั้งสี่จุด พรอมต์ตัวจัดเส้นทาง E1 ถูกออกแบบมาโดยเจตนาให้ไม่ขยายตัวเพิ่มขึ้น — มันมีไว้เพื่อหลีกเลี่ยงการเรียกที่มีค่าใช้จ่ายสูงทั้งหกครั้ง ดังนั้นจึงต้องไม่กลายเป็นครั้งที่เจ็ด

3. การเลือก & งบประมาณ — วิธีการสร้างบล็อก (zero-LLM)

ข้อผิดพลาดของรีจิสทรีในขั้นตอนใดก็ตามจะลดระดับลงเป็นบล็อกว่างเปล่า — ตารางสกิลที่เสียหายไม่มีทางทำให้รอบการเทรดหยุดชะงักได้

5. วงจรชีวิตของทักษะ — พื้นฐานเทียบกับกำหนดเอง

การซิงค์แคตตาล็อก (2026-08-02): เมื่อสกิลฐานดั้งเดิมถูกอัปเดตในแคตตาล็อก แถวข้อมูลจริง (prod row) ทุกแถวที่ยังคงตรงกับสิ่งที่แคตตาล็อกเขียนไว้ล่าสุดจะอัปเกรดโดยอัตโนมัติในการอ่านรีจิสทรีครั้งต่อไป — ลายนิ้วมือ (catalog_hash) ใช้แยกความแตกต่างระหว่างทั้งสอง แถวที่ผู้ดูแลระบบแก้ไขแล้วจะเลิกตรงกันและคงการแก้ไขนั้นไว้จนกว่าจะมีการรีเซ็ตอย่างชัดแจ้ง ซึ่งจะเปิดใช้งานการอัปเกรดอัตโนมัติอีกครั้งด้วย การปิดใช้งานสกิลเป็นสถานะของผู้ดำเนินการ ไม่ใช่การแก้ไข: สกิลที่ปิดใช้งานและไม่ถูกแก้ไขจะยังคงได้รับการอัปเกรดจากส่วนเนื้อหา (body) แต่ยังคงปิดอยู่

6. เลเยอร์ความปลอดภัย — เหตุใดข้อความพรอมต์จึงไม่สามารถเข้าถึงคำสั่งซื้อได้โดยตรง

Skill bodies เป็น admin-authored เท่านั้นใน v1 และถูกจำกัดขนาดสองครั้ง (4,000 ต่อ body ที่ route, 30,000 ต่อ prompt ที่ builder) แม้แต่ body ที่เป็นอันตรายก็ไม่สามารถข้าม layers 2–4 ได้ — เพราะทำงานอยู่นอก prompt

7. การใช้งาน — admin API และจังหวะเวลาการเผยแพร่

เรียกทำหมายเหตุ
GET /api/admin/skillsแสดงรายการ skills ทั้งหมด (base + custom)อ่านข้อมูลใหม่ ข้ามการใช้ cache
POST /api/admin/skillsสร้าง custom skillslug [a-z0-9-] ≤48 · body ≤4,000 · prompts ⊆ {light, trader, verifier, planner} · 409 เมื่อซ้ำ
PATCH /api/admin/skills/{slug}แก้ไข name/description/body/prompts/markets/priority/enabledทักษะพื้นฐานแก้ไขได้; slug ไม่เปลี่ยนแปลง
POST /api/admin/skills/{slug}/resetคืนค่าเริ่มต้นของแคตตาล็อก + เปิดใช้งานอีกครั้งเฉพาะพื้นฐานเท่านั้น — 400 สำหรับแบบกำหนดเอง
DELETE /api/admin/skills/{slug}ลบทักษะที่กำหนดเองพื้นฐาน → 400 "ปิดใช้งานหรือรีเซ็ตแทน"

การเขียนทุกครั้งจะถูกบันทึกไว้ใน admin_audit_log (skill.create / update / reset / delete) และทำให้แคชของโปรเซส API ใช้งานไม่ได้ทันที worker เป็นโปรเซสแยกต่างหากระบบจะปรับให้สอดคล้องกันผ่านค่า TTL 30 วินาทีของ registry — การแก้ไขจะไปถึงรอบการตัดสินใจถัดไปภายใน ~30 วินาที และฟลีตที่กำลังทำงานอยู่จะรับค่านั้นในรอบถัดไปของมัน (v1 จงใจไม่ล็อกสกิลไว้ตายตัวต่อการรัน แต่ละครั้ง; ดูส่วน non-goals ในเอกสารการออกแบบ)
