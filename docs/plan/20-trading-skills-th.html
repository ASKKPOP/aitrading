5. วงจรชีวิตของ Skill — base เทียบกับ custom

การซิงค์ Catalogue (2026-08-02): เมื่อ base skill ต้นฉบับถูกอัปเดตใน catalogue แถวใน prod ทุกแถวที่ยังคงตรงกับสิ่งที่ catalogue เขียนไว้ล่าสุดจะอัปเกรดโดยอัตโนมัติในการอ่าน registry ครั้งต่อไป — fingerprint (catalog_hash) ใช้แยกความแตกต่างระหว่างสองแบบนี้ แถวที่ admin แก้ไขแล้วจะหยุดการจับคู่และคงการแก้ไขไว้จนกว่าจะมีการ reset อย่างชัดเจน ซึ่งจะเปิดใช้งาน auto-upgrade อีกครั้งด้วย การปิดใช้งาน skill เป็นสถานะของผู้ดูแลระบบ ไม่ใช่การแก้ไข; skill ที่ถูกปิดใช้งานโดยไม่ได้แก้ไขยังคงได้รับการอัปเกรด body และยังคงปิดอยู่

6. ชั้นความปลอดภัย — เหตุใด prompt text จึงไม่สามารถเข้าถึงคำสั่งซื้อได้โดยตรง

Skill bodies เป็นข้อความที่เขียนโดยแอดมินเท่านั้นใน v1 และมีการจำกัดขนาดสองชั้น (4,000 ตัวอักษรต่อ body ที่ route, 30,000 ตัวอักษรต่อ prompt ที่ builder) แม้แต่ body ที่เป็นอันตรายก็ไม่สามารถข้ามชั้นที่ 2–4 ได้ — เนื่องจากมันทำงานนอก prompt
