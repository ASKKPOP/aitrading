One-line pitch
The user sets only N (number of runs) and presses go. The AI researches every automatable market, composes N runs with expected-profit theses, registers them on sooppiy.com/automation, trades each on its interval, and adapts every next step from the last result.

5 · Money-safety rails (자금 안전장치)

Anti-martingale ladder

Size after a loss can NEVER exceed size before it — property-tested + mutation-tested.

Layered stops

  • Cycle: confidence gate ↑ after losses, cooldowns, re-entry block (30m)
  • Run: max_loss / profit_target / at_time / drawdown brake 70% / adapt_retired (3 losses)
  • Fleet −30%: WARNING — SMS (reserved send budget) + email + in-app; members paused, replacements suspended; episode-latched so resume sticks (their responsibility from here)
  • Fleet −40%: STOP-ALL flatten + SMS — evaluated FIRST (gap ⇒ one stop-all), marked equity, fail-closed on stale marks, hard-clamped ≤40%
  • Account: master switch — hold / resume / remove ALL AI automation (fleet + runs + rules, every linked agent) with a zero-cost pre-gate so a held account cannot trade
  • Ops: FLEET_ENABLED off = no new builds, supervision keeps running

Budget invariant (perpetual N)

Σ ACTIVE member budgets ≤ total_budget at every tick

−40% stop-all fires at the first tick observing the breach (inter-tick overshoot possible — never promised away)

  • ONE equity everywhere: marked (realized + unrealized, fail-closed) — funds refunds AND rails, so unrealized losses cut replacement funding too
  • Slots persisted (fleet_slots): refund = min(original allocation, headroom) — a slot never grows; suspended at/below −30%
  • Unfundable slots go dormant, re-evaluated every tick (never sticky, never terminal); headroom subtracts zombie basis; same-tick fundings sequential

7 · State machines

Fleet

draft → researching → building → active ⇄ paused → stopping → stopped

  • partial build ≥1 run → active partial:k/N; zero → stopped(build_failed)
  • never auto-stops on empty: no candidates ⇒ replenishing:k/N, retried each tick; only user stop (or master switch) / −40% rail / agent_deleted end it — no equity-floor terminal (both attempted definitions were dominated by the −40% rail)
  • −30% rail ⇒ episode-latched warning: members paused, replacements suspended, SMS sent; user resume sticks (re-arms above −25%; fresh SMS per −5% leg)
  • one non-terminal fleet per USER ('user:{user_id}' DB UNIQUE); idempotency key on POST
  • lease-claimed (short committed claim txn — run protocol copied verbatim)

Member run (existing, + fleet hooks)

draft → armed → running ⇄ paused → stopping → stopped

  • new protective reason adapt_retired — excluded from auto-restart
  • fleet members NEVER auto-restart; replacement follows the per-stop-reason table (immediate: stop_event:* + adapt_retired · deferred: stop_eval_failed, synthetic_liquidation · never: user_stop, agent_deleted)
  • replacement fires once the member is terminal with no open position; stopped(positions_held) keeps its slot occupied (zombie basis reconstructed from signals replay + fresh mark, counted in equity, subtracted from headroom) until the position closes
