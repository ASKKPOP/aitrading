1. Gambaran umum — di mana skill berada dan di mana skill bertindak

Kotak putus-putus adalah asumsi lama yang harus dipatahkan oleh desain ini: repo skills/ adalah permukaan publikasi untuk agen eksternal dan dikecualikan dari Docker image — sehingga isi skill disimpan di DB, dan katalog dasar dikirim dalam kode dan melakukan seeding sendiri.

2. Alur siklus keputusan — di mana skill masuk ke dalam siklus trading langsung

💡 menandai empat titik injeksi. E1 router prompt sengaja tidak pernah berkembang — ia ada untuk menghindari enam pemanggilan yang mahal, jadi ia tidak boleh menjadi pemanggilan ketujuh.

3. Selection & budget — bagaimana blok dibangun (zero-LLM)

Kesalahan registry apa pun di langkah mana pun akan menurun menjadi blok kosong — tabel skill yang rusak tidak pernah bisa merusak siklus trading.

5. Siklus hidup Skill — base vs custom

Sinkronisasi katalog (2026-08-02): saat base skill asli diperbarui di katalog, setiap baris prod yang masih persis seperti yang terakhir ditulis oleh katalog akan otomatis upgrade pada pembacaan registry berikutnya — sebuah fingerprint (catalog_hash) membedakan keduanya. Baris yang telah diedit oleh admin berhenti cocok dan tetap mempertahankan edit tersebut hingga reset eksplisit dilakukan, yang juga mengaktifkan kembali auto-upgrade. Menonaktifkan skill adalah status operator, bukan edit: skill yang dinonaktifkan dan tidak disentuh tetap menerima upgrade body dan tetap off.

6. Lapisan keamanan — mengapa teks prompt tidak dapat langsung mencapai order

Skill bodies hanya ditulis oleh admin di v1 dan dibatasi ukurannya dua kali (4,000 per body di route, 28,000 per prompt di builder). Bahkan body yang bersifat hostile tidak dapat melewati lapisan 2–4 — lapisan-lapisan tersebut berjalan di luar prompt.

7. Mengoperasikannya — admin API + waktu propagasi

panggilanfungsicatatan
GET /api/admin/skillsdaftar semua skill (base + custom)pembacaan segar, melewati cache
POST /api/admin/skillsbuat skill customslug [a-z0-9-] ≤48 · body ≤4,000 · prompts ⊆ {light, trader, verifier, planner} · 409 jika duplikat
PATCH /api/admin/skills/{slug}edit nama/deskripsi/isi/prompts/markets/priority/enabledbase skill dapat diedit; slug tidak dapat diubah
POST /api/admin/skills/{slug}/resetpulihkan default katalog + aktifkan kembalihanya base — 400 untuk custom
DELETE /api/admin/skills/{slug}hapus skill custombase → 400 "disable atau reset saja"

Setiap penulisan dicatat dalam admin_audit_log (skill.create / update / reset / delete) dan langsung membatalkan cache proses API. worker adalah proses terpisah: ia menyesuaikan diri melalui TTL 30 detik pada registry — sebuah perubahan mencapai siklus keputusan berikutnya dalam ~30 detik, dan fleet yang sedang berjalan akan menerapkannya pada siklus berikutnya (v1 sengaja tidak membekukan skill per run; lihat non-goals pada dokumen desain).
