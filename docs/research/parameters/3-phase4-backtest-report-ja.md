### ウォークフォワード（フォールドごとにチューニング、6構成 — スヌーピングを考慮済み）

Every foldは`confluence_min=3`に調整済み；テストPF: F1 1.46、F2 1.82、F3 0.69、F4 0.79。エッジはレジーム依存であり、フォールドをまたいで持続しない — これは研究における「公表されたエッジは減衰する」という警告と一致する。

### 条件相関（統計的観点はこれを予測していた）

### 実際に機能したもの

F4のベア相場ウィンドウでは、戦略は資産ごとに約1.1〜1.7%の損失を出した一方、バイ・アンド・ホールドは**−21%（ETH）、−38%（BTC）、−47%（SOL）**の損失を出した。最大ドローダウンは2〜9%で、B&Hの過去のドローダウン60%以上と比較される。エクスポージャーは日数の3〜6%。**このシステムの検証された価値は、レジームフィルタリングとエグジットスタックによる資本保全であり — まさに研究が主張する「エッジはリスク管理から来るものであり、予測からではない」という点である。検証されていないのは単独での収益性である。**

## 3. 決定（事前登録されたルールに従って）

1. **転換なし。** `CONFLUENCE_GATE_ENABLED`、`REGIME_FILTER_ENABLED`、`VOL_SIZING_ENABLED`は**デフォルトでオフ**のままとする。プリセット／`min_confidence`の移行は出荷されない。計画自身の文言が支配する：*「[基準]を下回る場合、confluenceの閾値は本番ではなく研究に差し戻される。」*
2. **それでも出荷されるもの（すでにマージ済み、実行動作の変更はゼロ）：** confluence表示 + エージェントAPI、レジームアドバイザリー + タイル、テレメトリー（決定ごとのconfluenceベクトル、ファクタースナップショット）、安全性の修正（breakerのtripped_by/expires_at、SL/TPを緩めない、first_opened_at、リスク方向ゲーティング、put_risk_limitsの修復）、修復済みのバックテスターメトリクス、そしてオプトインのエージェントごとのエグジットツールキット（トレーリング／タイムストップ — 個々のエージェントがこれらを有効化できる；これらはポジショナルなリスクツールであり、収益性の主張ではない）。
3. **再評価パス:** ライブフォワード。Phase-1のテレメトリは、すべての決定について（B4を含む）完全な6条件ベクトルを蓄積する。ファクタースナップショットはfunding/OI/L-S/StockTwitsを記録する。≥400件のゲート済み品質のライブ決定が存在する場合（または将来のバックテストで欠落している条件を含められる場合）、基準を再実行する。キャリブレーションテーブル（コンフルエンス数ごとのヒット率、Wilson CI）はテレメトリから自動的に構築される。
4. **閾値の作業は研究に差し戻される：** データから浮かび上がる興味深い未解決の問いは、より単純なエントリーシグナルにおいて*エグジットスタック単体*（トレール＋タイムストップ＋レジーム拒否）が価値を持つかどうかである — ≥4/5のコンフルエンスエントリーゲートは非常に厳格で、3資産にわたり年6回しか取引されなかった。

*投資助言ではありません。シミュレータープラットフォームです。過去のエッジは劣化します。これらの数値は、記載されたスコープ制限のもとでの1回のバックテストを説明するものです。*
