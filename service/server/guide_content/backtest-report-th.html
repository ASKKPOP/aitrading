แบ็กเทสต์กลยุทธ์ Phase-4 — ผลการตัดสิน go/no-go

วันที่: 2026-07-16 · คำตัดสิน: INSUFFICIENT_EVIDENCE → แพ็กเกจ flip จะไม่ถูกนำไปใช้งานจริง เกตการทำงานทั้งหมดยังคงปิดเป็นค่าเริ่มต้น ตัวรัน: service/server/run_phase4_backtest.py · ข้อมูลดิบ: phase4-backtest-result.json · เอนจิน: backtest_strategy.py (ผ่านการทดสอบยูนิตแล้ว; รันอิสระสองครั้งได้ผลลัพธ์เหมือนกันทุกไบต์) แผน: docs/plan/04-ai-model-parameter-upgrade.md §Phase 4 — เกณฑ์ต่าง ๆ ถูกลงทะเบียนไว้ล่วงหน้าก่อนที่หน้าต่าง OOS จะถูกเปิดใช้งาน

0. สรุป

เมื่อพิจารณาตามเกณฑ์ที่กำหนดไว้ล่วงหน้า ผลลัพธ์คือ INSUFFICIENT_EVIDENCE — แพ็กเกจ flip (เปิดใช้งาน execution gates ตามค่าเริ่มต้น) ไม่ สามารถนำไปใช้งานจริงได้ การตั้งค่าที่สอดคล้องกับการใช้งานจริง (≥4/6) ให้ผลการซื้อขาย OOS เพียง 38 รายการตลอดช่วง walk-forward หกปี เทียบกับเกณฑ์ 400 รายการ และทั้งขอบล่างของ Wilson 90% สำหรับอัตราชนะ 36.8% (0.28) และขอบล่างของ profit factor แบบ bootstrapped (0.64) ต่ำกว่าเกณฑ์ที่กำหนด เมื่อผ่อนปรนไปที่แถว sensitivity (≥3) จำนวนรายการเพิ่มขึ้นเป็น 237 รายการ แต่ขอบล่างของ PF ยังคงอยู่ที่ 0.88 — ต่ำกว่า 1.0 จึงยังไม่สามารถยืนยันความสามารถในการทำกำไรได้ทางสถิติ

สิ่งที่พิสูจน์ได้ผล: ระบบจัดการความเสี่ยงทำงานตรงตามที่งานวิจัยคาดการณ์ไว้ — worst-asset maximum drawdown อยู่ที่ 2.6% เทียบกับ −38% ถึง −47% สำหรับ buy-and-hold ในช่วงเวลาเดียวกัน, 53% ของการออกจากการเทรดเกิดจาก trailing stop (ปล่อยให้กำไรวิ่งต่อ), และเงินทุนได้รับการรักษาไว้ด้วยการตัดขาดทุนมากกว่าการคาดการณ์ กรอบสถิติของแผงตรวจสอบได้ทำนายผลลัพธ์นี้ไว้ล่วงหน้าแล้ว: จำนวนการเทรดน้อยเกินไป

ขั้นตอนถัดไป: ทุกฟีเจอร์พร้อมส่งมอบในรูปแบบ display / advisory / opt-in อยู่แล้ว ประเมินระบบ six-condition อีกครั้ง รวมถึง B4 live-forward เมื่อข้อมูล live telemetry (confluence vectors, factor snapshots) สะสมเพียงพอแล้ว ค่า threshold ยังคงอิงตามงานวิจัย — ไม่ใช่การใช้งานจริง

1. การตั้งค่าที่ลงทะเบียนล่วงหน้า (ไม่เปลี่ยนแปลงหลังเห็นผลลัพธ์)

  • แถวหลัก: ค่าเริ่มต้นที่ตรงกับการใช้งานจริง (confluence_min=4, volume_confirm_min=1.5), ไม่เคยถูกปรับแต่ง — ไม่มีการ snooping โดยธรรมชาติของการออกแบบ
  • แถว Walk-forward: anchored, 4 folds, 14-day purge, 6-config grid (รายงานผล), ปรับแต่งบนชุด train ด้วย pooled profit factor (≥30 trades), fix ค่าบนชุด test
  • แถว Sensitivity: confluence_min=3 fixed (B4 เป็นค่า null ในเชิงประวัติศาสตร์ → บรรลุได้เพียง 5 จาก 6 เงื่อนไขเท่านั้น; ดังนั้น live gate จึงเข้มงวดกว่าใน backtest เมื่อเทียบกับการใช้งานจริง)
  • เกณฑ์: ≥400 pooled OOS trades มิฉะนั้น INSUFFICIENT_EVIDENCE · Wilson 90% lower bound ของ win rate > 0.50 · bootstrap 90% lower bound ของ profit factor > 1.0 · worst-asset max DD ≤ 30%
  • ความซื่อสัตย์ต่อขอบเขต: B4 เป็น null ตลอดทั้งช่วง; B3 ลดระดับเหลือ MA/RSI/volume; B5 = F&G leg เท่านั้น (คลังข้อมูลเต็มตั้งแต่ 2018 เป็นต้นไป, มี lag เพิ่มอีกหนึ่งวัน); S5 เป็น null; events = ปฏิทิน 2019–2025 ที่ผ่านการตรวจสอบแหล่งข้อมูลซ้ำสอง สินทรัพย์: BTC/ETH bars ตั้งแต่ 2019-01 (signals ≈2020-02 หลัง warmup 400-bar), SOL ตั้งแต่ 2020-04 (signals ≈2021-05) ค่าธรรมเนียม 0.1%/leg + slippage 0.05%; signal ที่ close-t จะ fill ที่ open t+1

3. การตัดสินใจ (ตามกฎที่กำหนดไว้ล่วงหน้า)

  1. ไม่มีการเปลี่ยนแปลง CONFLUENCE_GATE_ENABLED, REGIME_FILTER_ENABLED, VOL_SIZING_ENABLED ยังคง ปิดเป็นค่าเริ่มต้น ไม่มีการย้าย preset/min_confidence ออกใช้งาน ประโยคของแผนงานเองเป็นตัวกำหนด: "หากต่ำกว่า [เกณฑ์] เกณฑ์ confluence จะกลับไปอยู่ในขั้นตอนวิจัย ไม่ใช่ production"
  2. สิ่งที่จะนำออกใช้งานอยู่ดี (ผสานรวมแล้ว ไม่มีการเปลี่ยนแปลงพฤติกรรมการ execution): การแสดงผล confluence + agent API, regime advisory + tile, telemetry (confluence vector ต่อการตัดสินใจแต่ละครั้ง, factor snapshots), การแก้ไขด้านความปลอดภัย (breaker tripped_by/expires_at, never-loosen SL/TP, first_opened_at, risk-direction gating, การซ่อม put_risk_limits), ตัวชี้วัด backtester ที่ได้รับการแก้ไข และชุดเครื่องมือ exit แบบ opt-in ต่อ agent (trailing/time stops — แต่ละ agent สามารถเปิดใช้งานได้; เครื่องมือเหล่านี้เป็นเครื่องมือบริหารความเสี่ยงเชิงตำแหน่ง ไม่ใช่การรับประกันผลกำไร)
  3. แนวทางการประเมินซ้ำ: live-forward telemetry ของ Phase-1 จะสะสม vector ครบ 6 เงื่อนไข (รวมถึง B4) ในทุกการตัดสินใจ; factor snapshots บันทึก funding/OI/L-S/StockTwits เมื่อมีการตัดสินใจ live ที่ผ่านเกณฑ์คุณภาพ (gated-quality) ครบ ≥400 รายการ (หรือเมื่อ backtest ในอนาคตสามารถรวมเงื่อนไขที่ขาดหายไปได้) ให้รันเกณฑ์ใหม่อีกครั้ง ตาราง calibration (hit rate ต่อจำนวน confluence, Wilson CIs) จะถูกสร้างขึ้นเองจาก telemetry
  4. งานเกี่ยวกับ Threshold กลับไปสู่การวิจัย: คำถามเปิดที่น่าสนใจจากข้อมูลคือ exit stack เพียงอย่างเดียว (trail + time stop + regime veto) บนสัญญาณเข้าที่ง่ายกว่านั้นเป็นตัวสร้างมูลค่าหรือไม่ — confluence entry gate ที่ ≥4/5 นั้นเข้มงวดมากจนเทรดเพียง 6×/year ใน 3 assets

ไม่ใช่คำแนะนำการลงทุน แพลตฟอร์มจำลอง ความได้เปรียบในอดีตจะเสื่อมลงตามเวลา ตัวเลขเหล่านี้อธิบายผลการทดสอบย้อนหลังเพียงครั้งเดียวภายใต้ขอบเขตที่ระบุไว้ในเอกสาร
