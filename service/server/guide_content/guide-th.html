STEP 5Signal Fusion — สามกลุ่มสัญญาณ หนึ่งคะแนน

สัญญาณสามกลุ่ม — quant, sentiment, psychology — ถูกรวมเป็นคะแนนเดียวต่อสัญลักษณ์ เมื่อเปิดใช้ AI fusion (ค่าเริ่มต้นในระบบจริง) โมเดลจะพิจารณา factor snapshot ทั้งหมดด้วยตัวเองและคืนค่าน้ำหนักองค์ประกอบของตัวเอง ส่วนผลรวมถ่วงน้ำหนักคงที่ด้านล่างคือ deterministic fallback ซึ่งใช้เมื่อโมเดลไม่พร้อมใช้งาน แต่ละผลลัพธ์จะระบุแหล่งที่มา (AI / rule / rule-fallback) Read-only (GET); ขั้นตอนนี้ไม่มีการส่งคำสั่งซื้อขายใด ๆ

fallback = 0.5 × quant + 0.3 × sentiment + 0.2 × psych   (องค์ประกอบถูกจำกัดค่าไว้ที่ −1 ~ +1; ค่าที่ขาดหายจะถูกตัดออกและปรับสัดส่วนใหม่) ทั้งสองเส้นทาง: psychology จะไม่ทำการซื้อขายเพียงลำพัง และน้ำหนักของมันต้องไม่เกิน 0.3 — หาก AI ให้ผลลัพธ์ที่ขัดกับกฎนี้จะถูกยกเลิก

STEP 6การถกเถียงระหว่าง AI 4-Analysts + Trader — การตัดสินใจขั้นสุดท้าย

นี่คือเอนจินที่ทำหน้าที่ตัดสินใจเทรดจริง นักวิเคราะห์ทั้งสี่คนจะเขียนบทสรุปสั้นๆ ก่อน จากนั้นทีมเทรดเดอร์และทีมความเสี่ยงจะถกเถียงกันเพื่อสรุปเป็นการตัดสินใจเดียวพร้อมรายงานที่เป็นลายลักษณ์อักษร

  • เมื่อใช้ LLM — ผู้ให้บริการที่กำหนดค่าไว้ (OpenAI, Gemini, Grok, Qwen, GLM, local, OpenRouter, Anthropic) จะสร้างบทสรุปและบทถกเถียง
  • เมื่อไม่ใช้ LLM — ระบบสำรองแบบกำหนดตายตัวตามกฎเฉพาะแต่ละบทบาท (deterministic rule-based fallback) จะสร้างบทสรุปและการตัดสินใจในรูปแบบเดียวกันจากข้อมูลชุดเดียวกัน เอนจินจะไม่หยุดชะงักเด็ดขาด
  • บั๊กจริงที่พบและแก้ไขระหว่างการตรวจสอบแบบ red-team: ความมั่นใจในกฎแบบกำหนดตายตัวใช้ score แทน |score| ทำให้การตัดสินใจ sell ไม่สามารถเกิดขึ้นได้เลย → แก้ไขแล้ว (105d7e6).

STEP 7กฎการทำงานอัตโนมัติ — สิ่งที่ผู้ใช้เป็นผู้กำหนด

ขอบเขตและความเข้มข้นของระบบอัตโนมัติถูกกำหนดค่าโดยผู้ใช้ทั้งหมด การทำงานแบบอัตโนมัติ (automation tick) จะรันทุก 60 วินาที และดำเนินการเฉพาะกฎที่ "enabled and due" เท่านั้น UI มีสามโหมด — ① Simple (เลือกเพียงเหรียญและระดับความเสี่ยงที่ยอมรับได้) ② Standard (ปรับแต่งค่าที่แนะนำล่วงหน้า) ③ Expert (ควบคุมพารามิเตอร์ทั้งหมด)

STEP 8Risk Gate — รายการ "บังคับ" ของ Framework

ทุกคำสั่งอัตโนมัติต้องผ่านประตูตรวจสอบสามชั้น ไม่มีข้อยกเว้น ประตูนี้ทำได้เพียง ลดขนาด หรือ ปฏิเสธ คำสั่งเท่านั้น — ไม่สามารถเพิ่มขนาดคำสั่งได้

สูตร Kelly ทำอะไร

f* = W − (1 − W) / R   ·   W = อัตราชนะ, R = กำไรเฉลี่ย/ขาดทุนเฉลี่ย   ·   เพดานออร์เดอร์ = ½ f* × มูลค่าพอร์ต (เงินสด + มูลค่าสินทรัพย์ที่ถือครอง)
  • W และ R คำนวณจาก บันทึกการปิดสถานะของเอเจนต์เอง (จำลองย้อนหลังแบบ average-cost จำกัดที่ 5,000 รายการล่าสุด) — เป็นสถิติของตัวมันเอง ไม่ใช่ของผู้อื่น
  • หากมีการปิดออร์เดอร์น้อยกว่า 10 ครั้ง ยังไม่มีฐานทางสถิติเพียงพอ จึงไม่มีการปรับใดๆ (ป้องกันความมั่นใจเกินเหตุ)
  • f* ≤ 0 หมายถึง "ไม่มีความได้เปรียบ" — ออร์เดอร์ซื้อนั้นจะถูกปฏิเสธ ออร์เดอร์ที่ถูกลดขนาดลงจนต่ำกว่า $1 ไม่มีความหมาย จึงถูกปฏิเสธเช่นกัน

STEP 9การจับคู่คำสั่งและการจัดการโพซิชัน — ทั้งหมดเป็น Paper และบันทึกลงบัญชีแยกประเภท (Ledger)

การจับคู่คำสั่งใช้บัญชีแยกประเภทเดียวกันกับการเทรดแบบแมนนวลทุกประการ ได้แก่ แถวข้อมูล signals (signal_type='automation') + การอัปเดตโพซิชัน + การอัปเดตเงินสด + ค่าธรรมเนียม — ภายในธุรกรรมเดียว

  • ซื้อ: ตรวจสอบเงินสด → จับคู่คำสั่ง → บันทึก SL/TP ลงในแถวข้อมูลโพซิชันภายในธุรกรรมเดียวกัน (ค่าที่คำนวณจาก gate ค่าเริ่มต้น −5% / +10%)
  • ขาย: จะดำเนินการกับโพซิชัน long ที่มีอยู่แล้วเท่านั้น — มิฉะนั้นจะถูกข้ามไปพร้อมข้อความ "no long position to sell" ไม่มีการขายชอร์ต
  • หุ้นสหรัฐฯ: จะไม่มีการจับคู่คำสั่งขณะตลาดปิด — มีเพียงการวิเคราะห์และบันทึกเท่านั้น (บันทึก skip_reason)
  • การติดตามราคา: กำไร/ขาดทุนที่ยังไม่เกิดขึ้นจริง (unrealized P&L) คำนวณจากการ price_fetcher ดึงข้อมูลราคา ไม่ใช่จากโบรกเกอร์ — ตัวเฝ้าระวังจะตัดสิน SL/TP จากราคาชุดนี้
  • บัญชีจริง: กฎสำหรับ account_type='real' ยังคงรันการวิเคราะห์ แต่ โค้ดสำหรับส่งคำสั่งซื้อขายจริงไม่ได้ถูกเชื่อมต่อไว้เลยReal broker integration is a future phase as a separate subsystem.

§11สามมุมมอง — Trader · CEO · QA

Tมุมมองของ Trader — "ฉันจะเชื่อใจและใช้ระบบนี้ได้อย่างไร?"
  • วินัยถูกบังคับใช้ในโค้ด เพดานน้ำหนักจิตวิทยา (0.3), จำนวนตัวอย่างขั้นต่ำของ Kelly (10 เทรด), เกณฑ์ความเชื่อมั่น (0.65) — แม้มนุษย์จะตื่นเต้น แต่ระบบทำแบบนั้นไม่ได้
  • ทุกสัญญาณมาพร้อมประโยคหลักฐาน ไม่ใช่แค่ "BUY 0.36" แต่เป็น "ราคาสูงกว่า MA20 + funding เป็นกลาง + F&G ความกลัวสุดขีด ยังไม่เกิดการฟื้นตัว" — อ่านแล้วตัดสินใจว่าคุณเห็นด้วยหรือไม่
  • การขาดทุนถูกตัดที่สองชั้น ต่อโพซิชัน (SL −5%) และต่อบัญชี (รายวัน $1,000) การปิดของ watcher จะข้าม gate ไปได้ ดังนั้นการออกจากโพซิชันจึงเป็นไปได้เสมอแม้อยู่ในสถานะล็อกเอาต์
  • ลำดับการเรียนรู้ที่แนะนำ: ① เฝ้าดูสัญญาณอย่างเดียวสักไม่กี่สัปดาห์โดยปิด auto_execute → ② เมื่อสมุดบันทึกของคุณเองมีครบ 10 trades และ Kelly เปิดทำงาน ให้เริ่มทำอัตโนมัติด้วยขนาดเล็ก → ③ ปรับ min_confidence ให้เข้ากับอุปนิสัยของคุณเอง อย่าเร่งลดลงมาที่ 0.5 — ค่าเริ่มต้นแบบระมัดระวังที่ 0.65 มีไว้ด้วยเหตุผล
Cมุมมองของ CEO — "เหตุใดการออกแบบนี้จึงเป็นความได้เปรียบของผลิตภัณฑ์"
  • การวางตำแหน่ง: ไม่ใช่ "บอทที่การันตีผลกำไร" แต่เป็น Intelligent Automate Agent — แพลตฟอร์มของการรวบรวมสัญญาณที่วัดผลได้ + ระบบอัตโนมัติที่มีระเบียบวินัย ประโยคหลักฐาน สแนปช็อต และความสามารถในการตรวจสอบซ้ำคือจุดต่างที่สร้างความแตกต่าง และในเวลาเดียวกันก็ช่วยลดความเสี่ยงด้านกฎระเบียบและความเชื่อมั่น
  • Paper-first คือกลยุทธ์ การไม่เชื่อมต่อบัญชีจริงไม่ใช่ความไม่สมบูรณ์ แต่เป็นการออกแบบแบบเป็นขั้นตอน — ผู้ใช้ตรวจสอบความสามารถของระบบได้โดยไม่มีความเสี่ยง เราปรับปรุงเอนจินจากข้อมูลที่สังเกตได้ จากนั้นจึงเพิ่มการเชื่อมต่อโบรกเกอร์ (ซับซิสเต็มที่แยกออกไป)
  • โครงสร้างต้นทุน: ไปป์ไลน์ทั้งหมดในปัจจุบันทำงานบนแหล่งข้อมูลฟรี — ขยายขนาดได้โดยไม่มีต้นทุนส่วนเพิ่ม LLMs และข้อมูลแบบเสียเงิน (whale/liquidation) เป็นเลเยอร์เสริมที่จะเพิ่มเข้ามาหลังมีรายได้
  • ลำดับแผนงาน: P6 whale/liquidation (แหล่งข้อมูลแบบเสียเงิน) → การทำ backtesting ที่ลึกขึ้น → การเชื่อมต่อโบรกเกอร์จริง → agent marketplace แต่ละขั้นตอนต่อยอดจากข้อมูลของขั้นตอนก่อนหน้า
  • การบริหารความเสี่ยงคือแบรนด์: "แพลตฟอร์มที่การเทรดด้วยอารมณ์เป็นไปไม่ได้ในเชิงโครงสร้าง" เป็นทั้งข้อความทางการตลาดและข้อเท็จจริงในเวลาเดียวกัน — พิสูจน์ได้ด้วยโค้ด
Qมุมมองของ QA — "อะไรที่ได้รับการตรวจสอบ และตรวจสอบอย่างไร"
  • ผ่านการทดสอบมากกว่า 1,100 รายการ (รวมถึง 126 phase tests ใหม่: risk_engine·routes_risk·psych_feed·quant_crypto·scanner·signal_fusion·routes_signals·signal_feed_snapshot)

  • การยืนยันแบบ Live (2026-07-15): endpoint ของ fusion, psychology, scanner และ risk ทั้งหมดได้รับการยืนยันแล้วว่าให้บริการข้อมูลจริงบน sooppiy.com (F&G 25, BTC RSI 55.05, ผู้สมัคร scanner BSBUSDT ×3.52) ไม่มี regression
  • การยืนยันที่เหลืออยู่: การสังเกตการปิดของ watcher ในระยะยาว (เก็บข้อมูลการยิง SL จริงบน staging), การสะสม mention-baseline ของ scanner (≥3 สแกน), การมอนิเตอร์การตัดวงจรอัตโนมัติจริง (breaker trip) (3σ)
