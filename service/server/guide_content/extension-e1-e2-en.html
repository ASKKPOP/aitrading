E1 — Route by situation: AI for the tails, algorithm for the middle RECOMMENDED

Your idea: when analysis reads high-event / high-risk / high-profit, let the AI recommend and act (an algorithm can't encode every parameter of a tail situation). In normal conditions (hold / routine), act by the programmed deterministic algorithm — cheap, auditable, predictable. This is a sound architecture, and it directly fixes the cost problem of running full analysis on every cycle.

Why this is right
  • Cost: full AI only on ~15–20% of cycles → ~80% cheaper than the blanket full mode now running, while keeping AI exactly where human-factor judgment matters.
  • Auditability: normal ops are deterministic — reproducible, backtestable, explainable.
  • Tail quality: the tails are where Fleet 16 lost (rally against an all-short book) — precisely where the full desk should think.
Risks & guardrails
  • AI never bypasses the risk engine — both routes end at the same gates (Kelly, exposure, stops, trailing). Non-negotiable invariant.
  • Fail-closed: AI call fails on a hot cycle → hold + keep stops, never silently fall to the algorithm mid-event.
  • Threshold calibration needs the backtest harness (plan #1) — ship v1 with the conservative triggers above, tune with data.
  • Journal the route (route: ai|algo + trigger) in every decision event so behaviour is explainable per cycle.

E2 — Hot-issue daemon: hourly AI watch over every user's RUN symbols RECOMMENDED

Your idea: a daemon that, every hour, sweeps all symbols across all users' runs (e.g. 3 users · 11 symbols), detects hot issues (ROI shift, economy/policy change from any organization, technical breakout, news & social surge), notifies each affected user, and hands each user's Trading Master a decision point. The worker already snapshots every input feed — this is mostly assembly plus a fan-out layer.

Walk-through (your example, now case-by-case): 3 users hold 11 distinct symbols. Hourly tick scans all 11 at zero LLM cost; ETH trips (bearish policy headline + news burst). Stage-1 deep-reads the event once. Stage-2 then verifies per user: user A is short ETH → the news supports the position → low urgency FYI (or silence); user B is long ETH 2× with the stop 1.1% away → against the position and material → personalized urgent alert + Master decision point + next cycle routed to the full desk; user C holds ETH with a far stop and small size → below materiality → no alert at all. Same global fact, three different outcomes — and the other 10 symbols cost nothing.
Already exists (verified in prod)
  • Feeds: policy_feed · psych_feed (F&G, shock) · social_feed · market news / macro / ETF-flow snapshots — all on the worker schedule.
  • Notifications: send_alert with per-user language (5-lang catalogues live on prod), dedupe keys.
  • Master layer: ai_automation_state + fleet supervisor to receive/act on the signal.
To build
  • hot_issue_daemon.py worker task + hot_issues table (symbol, trigger, severity, ai_read, ts).
  • Trigger thresholds (z-scores vs each feed's own history) + per-symbol cooldown (no re-alert < N h at same severity).
  • E2-B′ per-user verification layer — join hot issue × each user's book (position sign, leverage, distance-to-stop, thesis); deterministic relevance/materiality filter, then one personalized AI verify per material user. Silent below threshold.
  • New i18n message ids for the alert catalogue (needs native review per memory note) — parameterized per-position wording.
  • Master "act on signal" — v1: notify + surface decision point + route next cycle to AI. Auto-trade on signal only as opt-in phase 2.
Main risk — alert fatigue: an hourly AI watcher that over-notifies gets muted within a week. The severity floor, per-symbol cooldowns, and "only on state change" rule are as important as the detection itself.

LLM cost — why routing beats blanket full mode

Daily decision-tier LLM calls for a 4-run fleet at 45-min cycles (32 cycles/run/day), plus the daemon over 11 symbols. E1 keeps the full desk exactly where it pays, at ~⅕ the cost of always-full. E2's pre-filter makes an hourly AI watch affordable.

Verdict: build both. E1 (~1–2 wk, E1-A shipped & live 2026-07-25) turns "full analysis always" into "full analysis when it matters". E2 (~1.5–2 wk) is the event radar — now 3-stage: detection is global; judgment is always per-user (a hot issue is a fact about the market; whether it matters is a fact about each user's book — verified case-by-case before any alert or act). Safety invariant throughout: AI recommends; the risk engine always disposes.
