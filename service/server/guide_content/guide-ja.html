ステップ 5シグナル融合 — 3つのファミリー、1つのスコア

クオンツ、センチメント、心理という3つのシグナルファミリーは、シンボルごとに1つのスコアへと融合されます。AI融合がオン（本番環境ではデフォルト）の場合、モデルはファクタースナップショット全体を独自に評価し、自身のコンポーネント重みを返します。以下の固定加重和は、モデルが利用できない場合に使用される決定論的なフォールバックです。各結果にはそのソース（AI／ルール／ルールフォールバック）がラベル付けされます。読み取り専用（GET）；このステップは注文を発注することはありません。

fallback = 0.5 × quant + 0.3 × sentiment + 0.2 × psych   （各コンポーネントは −1 ～ +1 にクランプ；欠損しているものは除外され再正規化されます）。両方の経路において：心理単独で取引されることは決してなく、その重みは0.3を超えることはできません — それ以外を主張するAI判定は破棄されます。

ステップ 6AI 4アナリスト＋トレーダー討議 — 最終判断

これは実際の取引判断を行うエンジンです。4名のアナリストがそれぞれ簡潔なブリーフを作成し、その後トレーダー＋リスクチームが討議して1つの判断と文書レポートを作成します。

  • LLMを使用する場合 — 設定されたプロバイダー（OpenAI、Gemini、Grok、Qwen、GLM、ローカル、OpenRouter、Anthropic）がブリーフと討議を生成します。
  • LLMを使用しない場合 — 役割ごとの決定論的ルールベースのフォールバックが、同じデータから同じ形式でブリーフと判断を生成します。エンジンは決して停止しません。
  • レッドチームレビューで発見・修正された実際のバグ：ルールベースの確信度がscoreの代わりに|score|を使用していたため、sell判断が到達不能になっていました → 修正済み（105d7e6).

ステップ 7自動化ルール — ユーザーが決めること

自動化の範囲と強度はすべてユーザーが設定します。自動化ティックは60秒ごとに実行され、「有効かつ実行時刻」のルールのみを実行します。UIには3つのモードがあります — ①シンプル（コインとリスク許容度のみ選択）、②スタンダード（推奨プリセットを調整）、③エキスパート（全パラメータ制御）。

ステップ8リスクゲート — フレームワークの「必須」項目

すべての自動注文は例外なく三重ゲートを通過しなければなりません。ゲートは注文を縮小または拒否することしかできません — 決して拡大はしません。

Kellyの公式が行うこと

f* = W − (1 − W) / R   ·   W = 勝率、R = 平均利益/平均損失   ·   注文上限 = ½ f* × 資産（現金＋保有評価額）
  • WとRはエージェントの自身の決済履歴（平均取得原価での再現、直近5,000件を上限）— 他者ではなく自分自身の実績から算出される。
  • 決済済みトレードが10件未満の場合は統計的根拠がないため調整は行われない（過信を防ぐため）。
  • f* ≤ 0 は「エッジなし」を意味し、その買いは却下される。$1未満に縮小された注文も意味を持たないため、同様に却下される。

ステップ 9約定とポジション管理 — すべてペーパー取引、すべて台帳に記録

約定は手動取引とまったく同じ台帳を使用する：signalsの行（signal_type='automation'）＋ポジション更新＋現金更新＋手数料 — すべて一つのトランザクション内で処理される。

  • Buy： 現金を確認 → 約定 → 同じトランザクション内でポジション行にSL/TPを登録（ゲートで計算された値、デフォルトは−5%／+10%）。
  • Sell： 既存のロングポジションに対してのみ実行される — それ以外は「no long position to sell」としてスキップされる。空売りは不可。
  • 米国株： 市場が閉まっている間は約定されない — 分析とログ記録のみ行われる（skip_reasonが保存される）。
  • 価格追跡： 含み損益はprice_fetcherのポーリングから計算され、ブローカーは介さない — ウォッチャーはこれらの価格に基づいてSL/TPを判定する。
  • 実口座： account_type='live'(旧real)のルールは接続済みの取引ゲートウェイへ実注文を送信します — 9取引所(Alpaca・Binance・IBKR + 2026-08地域拡張: Bybit・OKX・Kraken・Crypto.com・Upbit・KuCoin)。ブローカーごとの規約同意・ライブ許可リスト(新規取引所はshadow優先)・注文あたり$1,000の初期上限で保護されます。詳細は実取引ゲートウェイのドキュメント参照。

§113つの視点 — トレーダー · CEO · QA

Tトレーダーの視点 — 「このシステムをどう信頼し、使えばよいか？」
  • 規律はコードで強制される。 心理ウェイトの上限（0.3）、ケリー基準の最小サンプル数（10取引）、確信度ゲート（0.65） — 人間が興奮しても、システムは興奮しない。
  • すべてのシグナルは根拠となる文を伴う。 単に「BUY 0.36」ではなく「価格がMA20を上回る + ファンディングは中立 + F&Gは極度の恐怖、回復は未発火」— それを読んで同意するかどうかを判断する。
  • 損失は2つの層で制限される。 ポジション単位（SL −5%）とアカウント単位（1日 $1,000）。ウォッチャーによるクローズはゲートを迂回するため、ロックアウト状態でも常に決済は可能である。
  • 推奨される進め方： ①auto_executeをオフにして数週間だけシグナルを観察する → ②自分のジャーナルが10トレードに達しKellyがオンになったら、小さいサイズで自動化する → ③min_confidenceは自分の気質に合わせて調整する。0.5まで急いで下げないこと — 保守的な0.65のデフォルトには理由がある。
CCEOの視点 ——「この設計がプロダクトの優位性である理由」
  • ポジショニング: 「利益保証ボット」ではなく Intelligent Automate Agent — 測定可能なシグナル収集と規律ある自動化のプラットフォーム。エビデンス文、スナップショット、そしてレビュー可能性が差別化要因であり、同時に規制リスクと信頼リスクを低減する。
  • Paper-firstは戦略である。 すべてのルールはシミュレーターから始まる — ユーザーはリスクなしでシステムの実力を検証し、準備ができたらゲートウェイを接続してshadow(模擬比較)→live(実注文)へ段階的に移行する。実取引ゲートウェイはすでに稼働中です。
  • コスト構造: 現在のパイプライン全体は無料ソースで動作しており — 限界費用ゼロでスケールする。LLMと有料データ(whale/liquidation)は収益化後に追加されるオプションレイヤーである。
  • ロードマップの順序: P6 whale/liquidation(有料ソース) → より深いバックテスト → 実ブローカー統合 → エージェントマーケットプレイス。各段階は前段階のデータの上に構築される。
  • リスク管理がブランドである: 「心理主導のトレーディングが構造的に不可能なプラットフォーム」はマーケティング文句であると同時に事実でもある — コードで証明可能である。
QQAの視点 ——「何が検証されているか、どのように」
  • 1,100+件のテストが合格 (risk_engine·routes_risk·psych_feed·quant_crypto·scanner·signal_fusion·routes_signals·signal_feed_snapshotを含む126件の新しいフェーズテストを含む)。
  • テストで固定された安全不変条件: シミュレーターの約定のみ · 売却には保有ポジションが必要 · 市場閉鎖時はスキップ · 実口座への注文なし · ゲートは縮小/拒否のみ可能。
  • 全体を通じて適用されるFail-soft:外部ソースが失敗した場合、そのコンポーネントのみが除外され（missing 配列に記載）、残りのスナップショットは保存されます。不正な env ウェイトは 500 を返す代わりにデフォルトにフォールバックします。
  • ステージの分離： 5 つのフェーズすべてがデフォルトで env フラグ オフになっています — 本番インシデントの際は、1 つのフラグでそのステージだけを停止できます。
  • レッドチームの実績： 6 つの専門家視点とレッドチームレビューがデプロイ前に「sell unreachable」バグを発見・修正しました — レビュープロセスが実際に機能している証拠です。
